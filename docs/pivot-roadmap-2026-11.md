# Brain Flow 出海转向路线图

日期:2026-11-09 · 方法:roadmap-planning(精简版,单人开发)· 前置输入:`docs/code-audit-2026-11-09.md` + Google 联想词实测数据

---

## 0. 战略定调(Phase 1 输入汇总)

**业务目标(按优先级)**:
1. **有机流量**——月访问量(访问量本身就是当前阶段的核心产出)
2. **供给速度**——小游戏数量、单个新游戏的开发周期
3. **玩完率**——访客→玩完一局的比例(决定回访和分享)
4. 收入后置:门户分成(提交即得)+ 自有站广告(流量起来后)

**需求证据(2026-11-09 Google 联想词实测,非猜测)**:
- `memory games for adults / for seniors / for dementia / free online` —— 中老年记忆训练是真实搜索市场
- `reaction time test + spacebar / mobile / human benchmark / online` —— 反应力测试是成熟大流量品类
- `cognitive games for seniors / for stroke patients` —— 认知康复长尾
- `brain training games for adults`、`typing test wpm free online`、`math games for adults`
- **结论**:海外用户带着明确关键词找"免费在线、即点即玩"的脑力小游戏——与现有代码资产高度重合。

**产品定义(一句话)**:英文优先、无需登录、即点即玩的脑力小游戏矩阵站,每个游戏 2-5 分钟、手机浏览器流畅、有个人最佳成绩和分享卡。

**技术输入(来自审计)**:~2000 行可删;结算/商城有作弊漏洞和并发竞态;三个游戏引擎零共享;登录+经济+战役系统占后端复杂度的大头。

> **转向的重要红利:审计报告里的 Must-Fix #1(刷分)、#2(竞态)、#5(campaign 半成品)、#6(OTP)、#8(schema)会在砍掉服务端经济后自动消失**——没有服务端经济就没有可作弊的东西。真正必须修的只剩游戏层 bug(暂停软锁、engine 依赖、后台标签页、无时限)。

## 1. Epic 定义(Phase 2)

> 单人开发的工作量标尺:S = 1-3 天,M = 1-2 周,L = 3-6 周。

### E1 减法重构(The Cut)— M
- **假设**:砍掉登录/体力/商城/签到/战役/管理后台,只留游客模式,能让新游戏接入成本减半、包体显著变小,并消除全部服务端作弊面。
- **动作**:删 `api/`(保留静态站部署)、删 gameStore 的影子逻辑与导航切片(审计 #16)、删 5 个死文件与 ~90 个死 i18n key、路由收敛为 `/` + `/games/:slug`、**重写 CLAUDE.md**(现有内容已严重过时)。
- **成功指标**:src 体积 -40% 以上;新增一个游戏只需改 ≤2 个文件(注册表+游戏文件)。
- **业务结果**:供给速度。

### E2 引擎统一 + 游戏模板 — M(依赖 E1)
- **假设**:把三份重复的状态机/回合推进/summary/键盘处理抽成一个引擎核心后,新游戏只需写"出题+判题"差异,单个游戏从一周缩到 2-3 天。
- **动作**:按审计 #17 抽 `useGameEngine`(idle→play→feedback→finished + 得分 + localStorage 个人最佳 + 重玩);顺手修掉暂停软锁(审计 #3)和 engine-object 依赖问题(#4)——重构时这两个问题自然消解。
- **成功指标**:用它重写全部 4 个现有游戏;之后做一个全新游戏 ≤3 天。
- **业务结果**:供给速度、玩完率。

### E3 上线前硬化 — S(与 E1 并行)
- **假设**:门户审核员和自然流量访客对 bug 零容忍,上线前必须修掉游戏层四个 bug,否则被拒审/高跳出。
- **动作**:修暂停软锁(#3)、engine 依赖导致的幽灵事件/双音效(#4)、后台标签页 desync(#11,加 visibilitychange 自动暂停)、给数字模式接上现成的 AnswerCountdown 作答时限(#12)。
- **成功指标**:四个 bug 各有一个复现步骤并验证关闭。
- **业务结果**:玩完率、门户通过率。

### E4 首批游戏矩阵(Wave 1:10 个在线)— L(依赖 E2)
- **假设**:10 个关键词对口的在线游戏 → 每个游戏一个可索引页面 + 多个门户可提交的成品,长尾流量随数量累积。
- **首批清单**(前 6 个按搜索需求排序,后 4 个是现有改造):
  1. **Reaction Time Test**(反应力测试;联想词证明 spacebar/mobile 变体都有量)
  2. **Number Memory**(数字广度记忆)
  3. **Sequence Memory**(网格顺序记忆)
  4. **Stroop Test**(色词冲突,认知经典)
  5. **Math Sprint 60s**(60 秒口算,for adults 角度)
  6. **Visual Memory**(图案记忆)
  7-10. 现有四模式英文化重包装:N-Back Challenge / Spatial Memory / Mouse Tracker / People Counting
- **成功指标**:10 个游戏上线,每个有个人最佳成绩。
- **业务结果**:有机流量、供给速度。

### E5 SEO 站 — M(随 E4 逐个上线)
- **假设**:程序化落地页(`{域 名}/games/reaction-time-test`,标题"Reaction Time Test — Free Online")能在 8-12 周内吃到长尾词。
- **动作**:每游戏一页(可玩+说明+FAQ,首屏即玩);英文优先(i18n 翻转为 en 默认,zh 可选);JSON-LD `VideoGame` 结构化数据;sitemap+内链枢纽页("Memory Games for Seniors" 这类聚合页正好对上联想词);性能预算:LCP < 2.5s、首屏无滚动即可玩。
- **成功指标**:Google Search Console 收录页数、每周自然点击。
- **业务结果**:有机流量。

### E6 门户提交 — M(依赖 E3 + E2)
- **假设**:Poki/CrazyGames/GameDistribution/itch.io 提供冷启动流量和分成,比自建站 SEO 见效快。
- **动作**:每游戏出独立 HTML5 包(单文件嵌入、无外部登录、iframe 安全、遵守各家 SDK/广告规范);先投 CrazyGames/GameDistribution(门槛较低)练手,再投 Poki(门槛高、量大)。
- **成功指标**:≥3 个游戏被至少一家门户收录;门户侧游玩数。
- **业务结果**:有机流量(门户)、收入(分成)。

### E7 个人最佳 + 分享卡 — S(依赖 E2)
- **假设**:结果分享卡(成绩图,canvas 生成 PNG)会带来零成本的自传播。
- **动作**:localStorage 个人最佳 + 匿名昵称;分享卡含游戏名+成绩+二维码/链接;轻排行榜**先不做服务端**,门户有自己的分数体系。
- **成功指标**:分享率 >1% 的玩完局。
- **业务结果**:传播。

### E8 选题信号管线 — S(随时)
- **假设**:每周 10 分钟的趋势检查能持续产生对口选题,避免闭门造车。
- **动作**:写一个 20 行的脚本/清单:拉 Google 联想词(已验证可直读)+ Trends RSS(geo=US/GB/DE/JP),输出新词表;出现热点词(某事件/某梗)时评估"1 天蹭热点小游戏"。趋势对比曲线需要时再上 pytrends。
- **成功指标**:每周跑一次;每月从信号里产出 ≥1 个选题。
- **业务结果**:供给速度。

## 3. 路线图(Phase 4,Now / Next / Later)

```
NOW(第 1-3 周,承诺)
├─ E3 上线前硬化(4 个游戏层 bug,含复现验证)
├─ E1 减法重构(删服务端+死代码+路由收敛+重写 CLAUDE.md)
└─ E2 引擎统一 + 游戏模板(重构中顺带固化 #3/#4 的修法)
   里程碑 M1:纯静态站,4 个现有游戏英文版,零已知阻断 bug

NEXT(第 4-10 周,高置信)
├─ E4 游戏矩阵:先上 6 个新游戏(按清单顺序),再重包装 4 个旧游戏
├─ E5 SEO:游戏上线一个、落地页跟一个;聚合页(Memory Games for Seniors 等)
├─ E8 趋势管线跑起来(每周)
├─ E7 分享卡(第 2-3 个新游戏做完后接入模板)
└─ E6 门户提交:挑 3 个最 polished 的先投 CrazyGames/GameDistribution,再攻 Poki
   里程碑 M2:10 游戏在线 + 首批门户收录 + GSC 出现自然点击

LATER(第 3 个月起,探索)
├─ E4 Wave 2:扩到 15-20 个(选题由 E8 信号驱动,含热点小游戏实验)
├─ E9 变现:自有站广告位(流量门槛到了再动);门户分成自动累积
├─ 服务端排行榜回归(仅当流量证明需要;直接砍到只剩一个防刷接口)
└─ marketing-plan skill 全量跑一次(12 个月 AARRR 计划;触发条件:M2 达成后)
```

**依赖链**:E1 → E2 → E4/E7;E3 → E6;E4 ↔ E5(边上线边做页)。

**明确不做(以及为什么)**:账号体系回归(与即点即玩矛盾,砍掉的服务端问题不再回来)、体力/脑力币/商城/战役(服务于不存在的留存经济)、原生 App(SEO 流量进不了商店)、支付/IAP(没有可付费物)、en/zh 以外语言(先吃透英文市场)。

**风险与对策**:
- 门户拒稿(Poki 通过率低)→ 先 CrazyGames/GameDistribution/itch 练级,按反馈迭代。
- SEO 见效慢(8-12 周)→ 门户流量补即时性;聚合页打长尾而非大词。
- 单人带宽 → 模板化后每个游戏 ≤3 天是硬约束,超了先回头改模板。
- 砍掉的代码要找回 → 全在 git 历史里,真需要时 cherry-pick。
